/posts/123のようなURLは、listやformのような名前では振り分けられない。正規表現でパターンを当てる【ルーティング】

/posts、/posts/new、/posts/123 のように、Web アプリケーションでは URL の形でハンドラーを選びたい。パターンとハンドラーを add_route で登録し、match で正規表現を順に試して、パスに合うハンドラーを返す Router クラスを作ります。

ハンドラーを足すたびに、登録の行も1行ずつ伸びていく。アクション名からクラスを読み込んで作る【動的なクラス読み込み】

レジストリではハンドラーを使う前に全部登録しておく必要があり、10個、20個と増えると登録のコードも伸びる。'list' から Handler::List のようにクラス名を組み立て、Module::Load の load で読み込んで new する。登録しなくても名前だけでハンドラーが使えます。

ハンドラーが増えるたびに、set_handlerで1つずつ差し替えている。名前で登録して呼び分ける【レジストリ】

ハンドラーが増えると、どれをいつ set_handler で差し替えるかを呼び出し側が覚えておくことになる。名前とハンドラーの対応をハッシュの属性に持たせ、register_handler で登録しておき、dispatch('list') のように名前だけで呼び分けます。

Dispatcherに一度渡したハンドラーを、途中で切り替えられない。実行時に差し替える【roからrwへ】

handler 属性が is => 'ro' だと、一覧を表示していた Dispatcher をフォームの表示に切り替えられない。属性を is => 'rw' にし、意図が読み取れる set_handler メソッドを用意して、1つの Dispatcher のままハンドラーを差し替えます。

どのハンドラーを使うかの判断が、呼び出し側のあちこちに散らばる。振り分けを司令塔クラスに任せる【委譲（handles）】

利用側で ListHandler->new して run を呼んでいると、どのハンドラーを使うかの判断が呼び出し側に散らばり、ハンドラーを足すたびに呼び出し側も直すことになる。ハンドラーを属性に持つ Dispatcher クラスを作り、Moo の handles で run を委譲します。

runのつもりでexecuteと書いたハンドラーに、呼ぶまで気づけない。必須メソッドを起動時に確かめる【requires】

ハンドラーは run を持つ約束なのに、新しく足したクラスで execute と書いても、呼び出すまでエラーにならない。Moo::Role の requires 'run' で Handler ロールを作り、with で適用したクラスが run を持たなければ起動時に止めます。
