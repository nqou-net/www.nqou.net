Perl と Moo で作るローグライクの攻撃処理に、ログ・実績・サウンド・統計を足すたびに if/else が膨らむ困りごとを、通知先のクラス分けと登録の仕組みで解いて、最後に Observer パターンと名前を付ける全10回の連載の目次です。どこから読むか、困りごとからも選べます。

読了時間: 3分

Perl と Moo で作るテキストのローグライクに、通知の仕組みを育てていく全10回の連載です。敵を倒したらログに残すだけの素朴な実装から始め、実績を足したところで if/else が膨らむ困りごとを確かめ、通知を受け取るクラスの分離、update の約束（Moo::Role）、通知先を管理する Emitter、実行中の付け外し、型チェックと進めて、統計の追加と対話的な CLI で完成させます。最後の第10回で、作ったものが Observer パターンだったと名前を付けます。

各回は前の回のコードに手を足していく作りなので、通して読むなら第1回からが早道です。このページは目次を兼ねた案内板です。入口は「どこから読むか」で、困りごとが決まっているなら「困りごとから探す」で、順に追うなら「全話一覧」で選んでください。

どこから読むか

  • 第1回 — 最初から順に作るなら。敵を倒したらログに残す処理を、say で直接出力する素朴な実装で書く
  • 第2回 — 機能を足すたびにコードが膨らむ困りごとを、先に体感したいなら。ログに実績を足して、if/else が増える様子を確かめる。前提は第1回のコード
  • 第10回 — Observer パターンの役割と、Pub/Sub・Mediator との違いから知りたいなら。第9回までに作ったクラスを、パターンの役割に対応づける

困りごとから探す

機能を足すたびに、1つのメソッドが膨らむ

  • 第2回 — ログに実績を足したら、攻撃のメソッドが if/else だらけになった
  • 第3回 — ログと実績の処理を、メソッドから切り離したい
  • 第5回 — 通知先を呼ぶ処理を、ゲーム側に直接書きたくない

通知を受け取るクラスの書き方を揃えたい、間違いを早く見つけたい

  • 第4回 — update を書き忘れたクラスが、通知の時に初めて落ちる
  • 第7回 — 関係ないオブジェクトを登録しても、エラーにならない

実行中に通知先を切り替えたい

  • 第6回 — ゲームの実行中に、サウンドを ON/OFF したい

既存のコードに触れずに、機能を足したい

  • 第8回 — 統計の集計を、ゲーム本体を変えずに足したい
  • 第9回 — 全機能をまとめて、ダンジョンを探索できる CLI にしたい
