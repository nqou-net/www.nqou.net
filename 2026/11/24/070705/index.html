ログを足すと消えるバグは、もう一度起こさなくていい

ログを足すと消え、外すとまた起きる。締め切り直前の入札が、ときどき落札から漏れるバグ。失敗した一回の時刻・乱数・到着順を記録し、記録から同じ実行を何度でも再生して、止めても消えない状態で調べます（記録と再生）。

第1幕: 白いコマ

締め切りの直前に入れた入札が、今月三度、落札の判定から漏れた。ログを足すと、起きない。外すと、また起きる。いや、正確には、外してから起きたのは今朝の一度だけだ。でも、それで十分だった。

窓を雨が叩いていた。

ドックの事務所の二階で、わたしは長机にノートパソコンを開いていた。画面の真ん中で、変換の進み具合の棒がゆっくり伸びている。まだ半分にも届かない。

父の映像だった。父は港で潜水の仕事をしている。基金に頼まれて、引き揚げの前に、この船の船体を水中で調べに潜った。そのとき撮った記録映像が、父の古い機材の形式のままで、基金の事務所の機械では開けない。基金に渡す前に、ドックの事務所で再生できるようにしてくれ、と父に頼まれた。変換の道具を入れたノートパソコンを抱えて、朝から雨の中を来た。

濡れたコンクリートの匂いが、階段の下から上がってくる。窓の外では、クレーンの腕の先から雨だれが一本の線になって落ちていた。その向こうの甲板で、ときどき金具の鳴る音がする。高く、短く。

携帯が震えた。

市場の事務所からの転送だった。今朝のセリの件で、仲買人の上野さんから苦情が来ている、とある。締め切りの前に高い値を入れたのに、落札が別の仲買人になった。

わたしは港の魚市場の卸売会社で、システム課にいる。課は先輩とわたしの二人だけだ。保守しているのは電子セリで、前任の人から引き継いで三年になる。電子セリは、仲買人が手元の端末から値を入れ、締め切りの時刻に一番高い値を入れた人が落札する仕組みだ。同じ値が並んだら、くじで決める。

上野さんの文面は短かった。「二八〇〇で入れた。締め切りの前だ」

転送の下に、事務所の人の一行が足してあった。「どう返しますか」

返し方が分からなかった。

床に、水の落ちる音がした。

ぽたり、と一度。それから続けて。振り向くと、入口に合羽の人が立っていた。肩に、濡れたワイヤの束を掛けている。合羽のフードの下から、後ろで一つに束ねた黒い髪が見えた。

引き揚げ屋さんだった。父がそう呼ぶので、わたしもそう呼んでいる。顔は、父を迎えに来たときに何度か見ている程度だ。

引き揚げ屋さんは、挨拶より先に、床の古新聞の上へワイヤの束を下ろした。束が新聞に沈んで、灰色の水がにじむ。錆の匂いがした。ワイヤの端に、白いテープが巻いてある。テープには、ペンで何か書いてあった。

「磯部さんの映像は、開きましたか」

「あと少しです。いま変換しています」とわたしは言った。「すみません、父の機材が古くて」

引き揚げ屋さんは、長机の画面の棒を一度見た。急かす様子は無かった。

父から預かった紙を、わたしは鞄から出して渡した。撮影の一覧だ。潜った日と時刻、潜った場所、映像のファイル名が、父の字で並んでいる。

引き揚げ屋さんは一覧を上から読み、途中の一行に指を置いた。船の奥の、区画の名前が書いてある行だった。指を置いたまま、しばらく動かない。それから紙を、合羽のポケットにはしまわずに、机のわたしの側へ戻した。

窓の外を見た。甲板の方だった。

引き揚げ屋さんが入口へ向き直る。わたしは画面に目を戻した。

苦情の画面だ。

漏れた入札は、三度とも、締め切りの一秒以内に送られていた。送った時刻は、締め切りより前だ。端末が押した時刻が、入札に付いて届いている。なのに判定は、その入札を締め切り後として退けていた。

手元で何百回流しても、めったに起きない。起きたときに何が起きたか見えるように、締め切りの係の所にログを足した。締め切りの時刻が来たら合図を送る係だ。その合図を送る直前に、時刻を一行書き出すようにした。市場のサーバでは、ログはネットワークの向こうの共有ディスクのファイルへ書く。

足した日から、起きなくなった。

二週間、一度も起きなかった。ログが邪魔だったので、昨日の夕方に外した。今朝、起きた。

ほかの所にも足してみたことはある。端末の所と、判定の中。どこに足しても、当たりは減った。delve で締め切りの係にブレークポイントを置いて止めてみたこともある。止めると、起きなかった。

先輩は笑って、ハイゼンバグだな、と言った。見ようとして何かを足すと、起きなくなるバグのことだと、先輩は言った。冗談の語だと思っていた。

だから、ログを足さずに何度も流して、もう一度起きるのを待つしかない。起きたら、そのときに見る。それが、わたしの手の中にある一番ましな方法だった。

判定を書いてあるのは、auction.go の Apply だ。外から来る出来事を一つずつ受け取り、入札なら受け付けるか退けるかを決め、締め切りの合図なら落札者を決める。

// Apply は出来事を一つ適用する。
func (a *Auction) Apply(ev Event) {
	switch ev := ev.(type) {
	case Bid:
		ev.RecvAt = time.Now()
		if a.closed { // 締め切りのあとの入札
			a.rejected = append(a.rejected, ev)
			return
		}
		a.accepted = append(a.accepted, ev)
	case Deadline:
		a.closed = true
		a.winner, a.price = highest(a.accepted)
	}
}

本番の配線は run.go の Run にある。仲買人の端末ごとにゴルーチンが一本立ち、締め切りの係もゴルーチンが一本立つ。どれも同じチャネル events へ送る。受け手は一つずつ受けて、Apply へ渡す。

// Run は本番の配線。端末ごとのゴルーチンと締め切りの係のゴルーチンが、同じチャネルへ送る。
// 受け手が一つずつ受けて Apply する。
func (a *Auction) Run(terminals []Terminal) {
	events := make(chan Event)
	for _, t := range terminals {
		go func() {
			time.Sleep(time.Until(t.At))
			sent := time.Now()
			time.Sleep(t.Lag)
			events <- Bid{Buyer: t.Buyer, Price: t.Price, SentAt: sent}
		}()
	}
	go func() {
		time.Sleep(time.Until(a.deadline))
		events <- Deadline{}
	}()
	for range len(terminals) + 1 {
		a.Apply(<-events)
	}
}

どの端末の入札が先にチャネルへ入るかは、実行のたびに変わる。チャネルには入れ物が無いので、受け手が Apply している間、送り手は送ったところで待たされ、受け手が空くと待った順に一つずつ通される。コンパイルは通る。型の誤りは一つも無い。三年、この形で動いてきた。

手元では、実時間のゴルーチンで流すと、当たりを待つだけで日が暮れる。だから模擬を作ってあった。端末が時刻を押してから送り終えるまでの遅れを、種を固定した乱数から引く。普段は二ミリ秒まで、混んだときでも十五ミリ秒までだ。遅れを足した時刻の順に、出来事を Apply へ渡す。本番で実行のたびに変わる到着順の代わりに、種で決まる到着順を使う。同じ種なら、何度流しても同じ回で漏れる。

その模擬に、締め切りの係のログの書き出しの遅れも足せるようにしてあった。種 20260414 で千回のセリを流した結果がこれだ。

変換の棒が、端まで伸びた。

わたしは映像のファイルを開いた。

濁った緑の水だった。画面の右下の隅に、日付と時刻と水深が白い数字で焼き込まれている。数字は一秒ごとに進む。父のライトの輪が、船体の外板をゆっくりなでていく。錆の瘤が、輪の中に入っては出ていく。

背中に、雨の匂いが来た。

振り向かなくても分かった。引き揚げ屋さんが入口から戻ってきて、わたしの後ろに立っていた。合羽から落ちた水が、床で小さく鳴った。

映像は船の奥へ進んでいった。一覧の紙で、引き揚げ屋さんが指を置いた区画の名前の行のあたりだ。

画面が白くなった。

輪の中が、急に白く濁った。父のフィンが底の泥を舞わせて、そこにライトの光が当たると真っ白になる。父から何度か聞いた話だ。泥を舞わせたら終わりだ、と父は言っていた。何も見えなくなる。

わたしは一時停止を押した。

画面が、白いコマで固まった。隅の数字だけが、くっきり読める。

引き揚げ屋さんは野帳を抜き、画面の隅の時刻を写した。写し終えると野帳を閉じ、合羽のフードをかぶった。そのまま入口へ歩いて、雨の甲板へ出ていった。階段を下りる足音が、雨の音に紛れた。

わたしは巻き戻さなかった。

白いコマのまま、画面を置いた。窓を雨が叩いている。急いでいるのは、わたしの件のほうだった。上野さんへの返事を、先に考えたかった。

第2幕: 緩める前に

変換した映像を、基金のディスクへ書き出しはじめた。これも時間がかかる。棒が、また端から伸びはじめた。

窓から、甲板の端が見えた。マストの根元に、合羽の人が二人と、作業員が一人いる。何かを、端から順に触っている。

父の話には、ときどき引き揚げ屋さんが出てくる。あの人は、手を付ける前に全部書く、と父は言っていた。どういう意味か、聞いたことは無かった。

事務所の入口の傘立てから、一本借りた。

甲板は、雨で黒く光っていた。歩くと、靴の下で砂と錆の粒がこすれる。マストの根元まで行くと、上から雨だれが傘を叩いた。

マストを左右から、何本ものワイヤが斜めに支えていた。帆船のマストや帆を支えたり動かしたりする綱やワイヤを、まとめて索具という。その中で、マストを横から支えて動かないワイヤを、横静索という。英語ではシュラウドと呼ぶ、と作業員が教えてくれた。横静索の下の端は、甲板の金具につながっている。つなぎ目に、太いねじの付いた筒がそれぞれ入っていた。ターンバックルだ。ねじを回すと、ワイヤの張りを強めたり弱めたりできる。

その古いワイヤを、今日、全部外すのだと作業員が言った。新しいワイヤは、あとで張る。

作業員がスパナを持って、ターンバックルに手を伸ばした。

「まだです」

引き揚げ屋さんの声だった。作業員が手を止めた。

引き揚げ屋さんは、ターンバックルの前にしゃがんだ。筒の両端から、ねじ山が出ている。そこに金属の物差しを当てて、ねじ山の見えている長さを読んだ。野帳に一行書く。雨が野帳の紙を打ったが、引き揚げ屋さんは手で庇って書き続けた。

立ち上がって、ワイヤを手のひらで押した。押した手を離して、ワイヤがどれだけ戻るかを見る。もう一度押す。それから、携帯でターンバックルとワイヤの付け根を撮った。一枚。角度を変えて、もう一枚。

最後に、ペンキの小さな缶を開けて、ねじと筒にまたがるように、白い線を一本引いた。

「いいです」

作業員がスパナを当てて、ねじを回した。

ワイヤが、たわんだ。

張っていたワイヤが、少しずつ緩んで、垂れていく。最後には、マストの横で、雨に打たれてゆらゆら揺れるだけになった。さっきまでの、一本の線のような形は、もうどこにも無かった。

引き揚げ屋さんは、垂れたワイヤの端に白いテープを巻き、ペンで番号を書いた。野帳の行の頭に書いた番号と同じ数字だった。さっき事務所の床に下ろされた束の端にあったのも、この札だった。

次の一本へ移った。

物差しを当てる。書く。押す。撮る。線を引く。緩めさせる。札を巻く。

緩めたワイヤに、引き揚げ屋さんは二度と触らなかった。物差しも当てない。押しもしない。測り直さずに、次の一本の前へしゃがむ。

わたしは傘の下で、それを見ていた。

一本も、緩めたあとに確かめ直さない。

わたしは、いつも反対をしてきた。ログを足してから、もう一度起こして見ようとした。何かを緩めてから、測ろうとしてきた。白いペンキの線と、わたしの足したログの一行が、頭の中で隣どうしに置かれた。置かれたまま、つながらなかった。

雨脚が強くなった。

傘の上の音が変わった。粒が大きくなって、甲板に跳ねる。作業員が空を見上げ、引き揚げ屋さんがうなずいた。三人は手を止めて、工具をシートの下へ押し込んだ。わたしは先に事務所へ戻った。

事務所の給湯の棚に、電気ケトルがあった。水を入れて、スイッチを入れた。引き揚げ屋さんの分も、と思った。父が世話になっている人だ。

階段を上がる足音がした。

引き揚げ屋さんは、入口の手前で止まった。合羽の前を開けて、脱ぐ。袖を抜いて、裾を持って一度振った。水がまとめて床に落ちた。合羽を入口の釘に掛けてから、中へ入ってきた。下は、色あせた作業つなぎだった。上を脱いで腰で結んでいる。首にタオルを掛けていた。

ケトルが鳴った。湯を二つの紙コップに注いで、ティーバッグを落とした。一つを渡した。

「ありがとうございます」

引き揚げ屋さんは両手でコップを持って、窓の方を見た。

聞かずにいられなかった。上野さんの件と、どこかで重なる。どこが重なるのかは、言葉にならないままだった。

「さっきの、緩める前に測るのは」とわたしは言った。「外してからでも、確かめられませんか。外して、組み直して、同じように締めれば。そのとき測ればいいのでは」

言ってから、少し早口だったと思った。

引き揚げ屋さんは、コップを口から離した。

「組み直して締めた張りは、締めた人の張りです」

「同じように締めても、ですか」

「同じように、が分かりません」と引き揚げ屋さんは言った。「二十年、海の底で張っていた張りです。誰も同じようには締めていません。緩めたら、元の張りは戻りません。だから、緩める前に残します」

わたしは、自分のコップに湯を足した。足す必要は無かった。

わたしの側の数を、頭の中で数えた。何百回流したか。そのうち何回起きたか。今朝のは何回目か。数は出てくる。でも、二十年張っていた張り、に当たる数がどこにも無かった。探して、見つからなかった。

引き揚げ屋さんの目が、机の上に下りた。

開いたままの、わたしの画面だった。上野さんの苦情の転送が、開いたままになっていた。「締め切りの前だ」の一行が、大きく見えた。

「市場のセリの、システムなんです」とわたしは言った。画面を少し引き揚げ屋さんの方へ向けた。「締め切りの直前に入れた入札が、ときどき、締め切り後として退けられるんです。今月三度目で、今朝の分は、それで落札者が変わりました」

引き揚げ屋さんは、画面をのぞいた。

「送った時刻は締め切りより前で、それは入札に付いて届いています。なのに退けられる。見ようとしてログを足すと、起きなくなるんです。止めても起きない。だから今は、何も足さずに何度も流して、もう一度起きるのを待っています」

一息に言った。言い終えてから、少し言い直した。

「待っている、というか。それしか無いと思っています。時間が絡んでいるのは確かなんです。締め切りの一秒以内のものだけですから」

「そこは、同じ見立てです」と引き揚げ屋さんは言った。「時間です」

それだけだった。わたしは、続きを待った。

引き揚げ屋さんは、画面の横の、もう一つのウィンドウを見た。父の映像の、白いコマのままのウィンドウだった。

「磯部さんの機材は、撮るとき、映像のほかに何を残していますか」

意外な問いだった。少し考えた。

「隅の数字です。日付と時刻と、水深」とわたしは言った。「父は、潜る前に、機材の時計を船の時計に合わせると言っていました。だから、どのコマにも、いつ、どの深さか、が付いています」

引き揚げ屋さんは、うなずいた。

コップの湯を飲んだ。窓に近づいて、雨の粒の大きさを見た。窓ガラスを伝う筋が、さっきより細くなっていた。

わたしは、なぜそれを聞かれたのか分からなかった。画面の白いコマを見た。隅の数字だけが、くっきりと読めた。

迷った。

もう一度起こすのをやめるとしたら、何を見ればいいのか。起きた一回は、もう過ぎてしまった。今朝の一回は、本番のサーバの上で、誰も見ていないうちに過ぎた。取っておいたものは、何も無い。

次に起きたときのために、何かを残しておくしかない。でも、これまで足したログは、消える。足さなければ、何も残らない。

そこまで考えて、少しだけ考え直した。

ログが消えたのは、足した場所が悪かったからではないか。締め切りの係や判定の中は、処理の途中だ。処理の途中に書き出しを挟んだから、順が変わった。だったら、値が生まれる所で控えればいい。端末と締め切りの係が、送る前に、自分の出来事を控える。判定の処理には、指一本触らない。それなら消えないはずだ。

外から入ってくる値だけを、生まれた所で控える。控えたものは確実に残るように、そのつどファイルへ書く。

基金のディスクの書き出しが終わるまでの間だけ、と決めた。棒は、まだ三分の一だった。

引き揚げ屋さんは、入口の釘から合羽を取った。窓の外の雨は、弱まっていた。

わたしは、エディタを開いた。

第3幕: 起きた一回

まず、紙に書き出した。

ノートパソコンの横に、一覧の紙の裏を広げた。わたしのプログラムが、外から受け取っているもの。判定の Apply に、外から入ってくる値。

一つ目は、入札が届く順だ。どの端末の入札が先にチャネルへ入るかで、判定が変わる。入札の中身、つまり仲買人と値と送った時刻も、ここに含まれる。

二つ目は、時計の値だ。Apply は入札を受けたとき、time.Now() を読んで、受け取った時刻 RecvAt を入札に書き込む。

// Apply は出来事を一つ適用する。
func (a *Auction) Apply(ev Event) {
	switch ev := ev.(type) {
	case Bid:
		ev.RecvAt = a.clock.Now()
		if a.closed { // 締め切りのあとの入札
			a.rejected = append(a.rejected, ev)
			return
		}
		a.accepted = append(a.accepted, ev)
	case Deadline:
		a.closed = true
		a.winner, a.price = highest(a.accepted, a.lottery)
	}
}

記録と再生（Record & Replay）。実行中に外から入る非決定的な値、たとえばシステムコールの結果やスレッドの切り替えのタイミングを記録する。再生のときに同じ値を与え直して、同じ実行を決定的に繰り返す。論文の説明は、そういう意味のことを言っていた。rr は、プログラムとカーネルの境目、システムコールの結果とスレッドの切り替えの所で記録する。

使えない道具の説明を、それでも読み進めた。

// Apply は出来事を一つ適用する。
func (a *Auction) Apply(ev Event) {
	switch ev := ev.(type) {
	case Bid:
		ev.RecvAt = a.clock.Now()
		if a.settled || ev.SentAt.After(a.deadline) { // 締め切りのあとに送った入札
			a.rejected = append(a.rejected, ev)
			return
		}
		a.accepted = append(a.accepted, ev)
	case Settle:
		a.settled = true
		a.winner, a.price = highest(a.accepted, a.lottery)
	}
}

直した版で、さっきの記録を再生した。

ただ、ここで一つ、記録に無いものを足した。記録は直す前の版で取ったので、確定の合図 Settle が入っていない。直した版は、Settle を受けるまで落札を決めない。だから、記録の最後に、猶予のあとに締め切りの係が送るはずだった Settle を一つ足して与えた。記録そのものではなく、わたしが足した合図だ。

第4幕: 名前を付けて残す

雨が上がりかけていた。

窓ガラスの筋が、途切れ途切れになっている。甲板の方から、ワイヤを引き出す音がした。巻いた束がほどけて、鋼が甲板の上を擦っていく。新しいワイヤだ。

わたしは紙の裏を見ながら、確かめたことと、確かめていないことを分けた。

わたしが確かめた範囲は、市場のサーバの、一つのプロセスの中に収まる。Auction が受け取る三つの値、到着順と時刻とくじを、受け手の所で記録した。記録した入口の内側なら、何度再生しても、同じ一回が同じように起きる。止めても、ログを足しても、待たせても。

記録の外は、再生できない。市場の在庫のサーバの中で起きたことは、記録に入っていない。ネットワークの向こうで何が起きたかも、入っていない。入札がネットワークを渡ってくる途中の出来事は、届いた順と送った時刻の形でしか記録に残らない。

rr なら、もっと外側で記録する。プログラムとカーネルの境目だ。ネットワークから受け取った値も、プロセスが受け取った結果として記録に入る。それでも、記録していない別のプロセスと共有メモリで書き合うと、再生できない、と公式サイトにあった。外側で記録しても、記録の外はある。わたしの記録は、それよりずっと内側の、Auction の入口で取っている。

直し方にも前提がある。猶予の三百ミリ秒は、端末が送り終えるまでの遅れの最大より長い、と決めておいた。ネットワークが途中で切れて、それより長く遅れる入札は、この直し方では救えない。締め切り前に送っていても、確定のあとに届けば退けられる。

本番には、受け手で取る記録を常に入れることにした。メモリに足すだけの、recordingB の形だ。一回のセリで受け取る出来事は、多くても数百件。メモリはそれで足りる。セリが終わったら、判定で退けた入札の中に、送った時刻が締め切り以前のものがあるかを見る。あれば、そのセリの記録だけをファイルへ書き出す。ほかの記録は捨てる。

野帳の写し

  • 見たこと: 横静索のターンバックルを、緩める前に、一本ごとに、ねじ山の見えている長さを測り、たわみを確かめ、写真を撮り、印を付けました。緩めたあとは測り直していません。磯部さんの件: 送る前にファイルへ書く記録では、1000回で漏れる回が1回から2回に増えました。受け手でメモリに足す記録では、1000回とも記録なしと一致し、失敗の一回を100回再生して、100回とも同じ入札が退けられました
  • 思ったこと: 磯部さんは、バグを見るには、もう一度起こすしかないと見ていました。起こし直さず、起きた一回を記録から再生して、止めても同じ所で退けられるのを見ました。もう一度起こした実行は、起きた一回とは別の実行です。私は、組み直して締めた張りも、元の張りではないと見ています
  • 調べ方: 記録と再生（Record & Replay）。実行中に外から入る非決定的な値を記録し、再生のときに同じ値を与え直して、同じ実行を決定的に繰り返します
  • 固定したもの: 失敗した一回の記録ファイル seri-20260414-0630.json（セリの日付と締め切りの時刻）と、それを読む再生テスト。本番では、受け手でメモリに足す記録を常に取り、締め切り前に送った入札を退けたセリの記録だけを書き出します
  • 変えていないもの: 記録と再生の仕掛けは、製品の落札者・値・退けた入札・受け取った時刻を変えていません（模擬の上で、受け手でメモリに足す記録の、あり・なしで1000回とも一致）。ログと処理時間は、比べる対象に入れていません。送る前にファイルへ書く記録は、実行の順を変えたので使っていません
  • まだ見ていない所: 記録していない入口から入る値。市場の在庫のサーバと、ネットワークの向こうで起きたこと。猶予の300ミリ秒より長い遅れ
  • 船について: （記録）引き揚げ前の水中調査の映像に、区画の水密扉の下の縁と枠の隙間へ、角材が打ち込まれているのが映っています。打ち込んだ人は映っていません
