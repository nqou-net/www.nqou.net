第1幕: 検分 ── 表の戸口

今朝の素屋根は、光が弱い。

薄曇りで、隙間から差す筋は細く、鉋屑が舞っても、光の中を降りてこない。表の戸口の土間には、夏のあいだ入れていた葦戸が外されて、壁に立てかけてあった。通りを人が行き来するので、戸口の半分には養生の板が渡してあり、店の人はその脇を通っていく。クロベさんとナギさんは、板の内側で、新しい板戸を敷居の溝へ入れようとしていた。板戸は、昨日の夕方に建具屋から届いたものだった。冬のあいだ、葦戸の代わりに立てる戸になる。

package Omote::Shirase;
use strict;
use warnings;

# 使う側。渡された line に対して、三つの名前だけを呼ぶ。
sub new {
    my ($class, %args) = @_;
    return bless { line => $args{line}, log => [] }, $class;
}

sub close_day {
    my ($self, $text) = @_;
    $self->{line}->open_line;
    $self->{line}->send_notice($text);
    return 'day closed';
}

sub close_month {
    my ($self, $text) = @_;
    $self->{line}->open_line;
    $self->{line}->send_notice($text);
    $self->{line}->close_line;
    push @{ $self->{log} }, 'month closed';
    return 'month closed';
}

# 控え（月末の締めが済んだ記録）
sub log_entries {
    my ($self) = @_;
    return @{ $self->{log} };
}

1;

第3幕: 手立て ── 寸法を先に書く

クロベさんは、表の紙を、机の真ん中へ寄せた。

「この表は、紙の上にしかありません。機械には、読めない。使う側が呼んでいる名前だけを取り出して、替えの部品が満たすべき形として、一か所に書いておく。その技法を、インタフェースの抽出、Extract Interface と呼びます」

形、というのは、この三つの名前のことです、とクロベさんは言い足した。以降、形も、名前の一覧も、同じものを指す。

Michael Feathers の『Working Effectively with Legacy Code』に載っている技法だった。Java のように、interfaceを書ける言語が前提になっている。本の例では、描画の部品が使う側に必要なのは、点を打つ一つだけだった。だから、インタフェースにも、その一つだけを書く。使う側が必要としない名前は、入れない。私は、この二文を野帳に書いた。手順そのものは、本の言い回しではなく、今日の Perl での形で見せる、とクロベさんは言った。

「他の言語には、満たすべき形を書く場所があります。Perl には、その場所がありません」

Perl は、型を宣言しない。部品が、呼ばれた名前のメソッドを持っていれば、動く。持っていなければ、呼ばれたその場で止まる。この動き方は、前に印字の部品を替えたときに見たものと同じだった。今日はそれを、説明し直さない、とクロベさんは言った。

「場所が無いなら、場所を作ります。ただの名前の一覧を、一つのファイルに書きます」

package Omote::Sunpo;
use strict;
use warnings;

# 使う側（Omote::Shirase）が line に呼ぶ名前だけ。Ita の history / clear は入れない。
our @REQUIRED = qw(open_line send_notice close_line);

sub required { return @REQUIRED }

# bless 済みのオブジェクトかクラス名を渡す。欠けた名前を並べて返す。
sub missing {
    my ($thing) = @_;
    return grep { !$thing->can($_) } @REQUIRED;
}

1;

「ここでいう寸法は、この名前の一覧のことです」

クロベさんは、パッケージの名前を指した。Sunpo。戸口の九分とは別のもので、同じ言葉で呼んでいる。以降、コードの話では、この言葉は、名前の一覧のほうを指す。戸口の話をするときは、戸口の、と付ける。

qw(...)は、空白で区切った文字列の並びを作る書き方だった。ourは、パッケージ変数に、この場所からも名前で届くようにする宣言で、前に使ったものと同じ。新しいのは、次の二つだった。

「canは、オブジェクトやクラスの名前に、->can('名前')と続けて呼ぶと、その名前のメソッドを持っていれば、そのメソッドへの参照を返し、持っていなければ、何も返さない組み込みです。親から受け継いだ名前も、持っているものに数えます」

返ってくる「メソッドへの参照」は、その名前の処理を、あとから呼べる形にしたものだった。ここでは、あるかないかの判定にだけ使う。

もう一つのgrepは、条件に合う要素だけを、並びから取り出す組み込みだった。ここのgrep { ... }は、さっき端末で打ったgrepコマンドとは、名前が同じだけの、別のものだ。一覧の名前を一つずつ取り、canで持っていない名前だけを残して返す。canは持っていなければ何も返さず、それは偽として扱われる。!で逆にするので、持っていない名前だけが残る。返ってくるのは、欠けている名前の並びになる。

検めは、緑のままだった。実際に呼ぶと、板でも書状でも止まる。本物の知らせ板もretryを持っていないので、これは、替えの落ち度ではない。

「使う側が変わったときは、一覧は、誰が直すんですか」

私が訊くと、クロベさんは、短く答えた。

「人です。この検めは、一覧に書いてある名前を見ているだけで、使う側を見てはいません。一覧は、使う側の写しです。写しは、元が変われば、古くなります」

私は、野帳を開いた。一覧を直すのが人なら、その人は、使う側が変わったと、いつ知るのだろう。

「使う側に、呼ぶ名前を足す話は、私のところにも来ます。そのときは、一覧のことを、私から先に訊きます」

クロベさんは、うなずいた。私は、その一行を、野帳に書いた。

戸口の溝を彫り直したのに、墨で書いた九分が古いまま。そういう古さが、ここにも起こりうる。

クロベさんは、この手立てで言えることを、先に三つ言った。

「使う側と本物は、一字も変えていません。使う側が呼ぶ三つの名前が、本物にも、替えにも、代役にも揃っています。月末を待たずに、欠けた名前を、名前で言えます」

それから、言えないことを、一つずつ見せた。ナギさんが、canの見えないものを、実際に動かして並べた。

Wrongは、渡された知らせを捨てて、意味のない文字列を返すsend_noticeと、呼ばれたら必ずdieするclose_lineを持つ部品で、名前の有無だけを見る検めは「欠けなし」と答えた。Childは、三つの名前を全部、親から受け継いでいる。名前の有無だけを見る検めは、これも「欠けなし」とする。AutoLineは、持っていない名前の呼び出しを、まとめて自分で受ける仕組みを持つ部品で、実際には、呼べる。それなのに、検めは、三つとも欠けと答えた。canは、その仕組みで受ける名前が見えない。四行目は、bless されていない参照を渡したときで、canの呼び出し自体が止まる。最後の行は、AutoLineのclose_lineを、実際に呼んだ結果だった。

「見えるのは、名前の有無だけです」

クロベさんは、ナギさんの出力の脇に、七つの行を書いた。

言えないことわけ

受け継いだ名前の中身が合っているか持っている名前に数える。Childを動かした結果
持っていない名前をまとめて受ける部品見えず、欠けと出る。AutoLineを動かした結果
一覧と使う側のずれ検めは使う側を見ない。retryを動かした結果
bless されていない参照検めに渡せない。止まる
書状が店主の手に届くか見ていない。今日見たのは、一度動かした範囲
知らせの中身が正しいか見ていない

「最後の二つは、今日の検めの外です」

クロベさんは、鉛筆を置いた。

「今日の検めは、一度動かした話です。毎月、届き続ける保証では、ありません。もう一つ、入れていないことがあります。組み立ての時点で、欠けた名前を止める仕掛けです。入れると、これまで動いていた毎日の締めまで、止まる日が出ます。振る舞いが、変わってしまいます」

「シオリさん、これを通してください」

私は、検めのファイルを開いた。三つの部品を並べた行の最後に、その名前を足した。useの行も一つ足して、走らせた。

夕方、私は、表の戸を閉めに出た。

朝に入れた板戸を、溝に沿って滑らせる。戸は、最後まで滑って、溝に収まった。軽く手を添えると、音も立てずに閉まる。戸の下をのぞくと、敷居の内側に、墨で小さく、九分、と書いてあるのが見えた。

普請控

  • 見立て: 知らせ先を板から書状に替えたところ、毎日の締めは通ったが、月末の締めだけが、書状に無い名前を呼んで止まった。使う側がどの名前を呼んでいるのかは、どこにも書かれておらず、替えを書く人は、使う側を読み取るほかなかった
  • 手を入れた所: インタフェースの抽出（Extract Interface）を使った。使う側が呼ぶ三つの名前をOmote::Sunpoに一覧として書き、本物の知らせ板・書状・検め用の代役に、同じ検めを通して、欠けた名前を名前で言えるようにした。書状には、欠けていたclose_lineを一行足した
  • 触っていない所: 使う側のOmote::Shirase（毎日の締めと月末の締めの呼び方）、本物の知らせ板Omote::Ita（historyとclearは使う側が呼ばないので、一覧に入れていない）、本番の組み立ての書き方（line =>の右側だけが替えの違い）は、一字も変えていない。canが区別できない所（引数と中身・受け継いだ名前の中身・まとめて受ける仕組みの名前）、一覧と使う側の呼び出しを突き合わせる仕掛け、書状が店主に実際に届くかどうかは、見ていない
  • 次の工程へ送ること: 組み立ての時点で、欠けた名前を止める仕掛けと、一覧と使う側の呼び出しを突き合わせる検めは、今日は置かない。前者は、これまで動いていた毎日の締めまで止めてしまい、振る舞いが変わるため。後者は、使う側の呼び出しが決まった書き方のうちは拾えても、名前を組み立てて呼ぶ所は見落とすため、呼び出しがどこに集まっているかを見てからにする
  • 私が引き受けたこと: 替えが寸法に合うかどうかを、私が自分の検めで確かめられる。ナギさんが用意した、何が抜けているかを聞かされていない替えに検めを通し、欠けた名前を読んで返した。使う側に呼ぶ名前を足す話を聞いたら、一覧のことを私から先に訊く、と決めて、野帳に控えた
