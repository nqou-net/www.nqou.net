キャッシュの時間を短くするのは、やめた。何秒にしても、その秒数のあいだは、運休したあとの整理券が使えてしまう。

鷹宮さんは、フードコートの前に立って、観覧車のほうへ拳を振った。

鷹が、拳を蹴って飛び立った。低く、速かった。自分はテーブルから、その背中を目で追った。観覧車の骨組みのカラスが、気配に気づいて首を伸ばした。

鷹は、観覧車へは行かなかった。

途中で弧を描いて向きを変え、フードコートの屋根へ戻っていった。さっき、ほうびをもらった屋根だ。縁にとまって、翼をたたんだ。観覧車のカラスは、首を引っ込めて、また並び直した。

鷹宮さんは、黙って左腕を高く掲げた。鷹が屋根から降りてきて、拳にとまった。鷹宮さんは、鷹の胸のあたりを少しのあいだ見ていた。それから、フードコートの外のフェンスまで歩いて、鷹をフェンスの上にとまらせた。

「疲れてる。少し休ませます」

それだけ言って、フェンスの横に立った。

自分は、ノートパソコンに目を戻した。待つあいだに、昨夜の会話の履歴をさかのぼることにした。

ここで、会話というものを、自分の言葉で整理しておく。Claude Code で AI に頼みごとをすると、そのやりとりは一つの会話（セッション）としてつながっていく。こっちが新しい会話を始めないかぎり、前のやりとりは全部、同じ会話の中に残っている。AI が答えるときに読んでいるのは、いま書いた一文だけではない。その会話でこれまでにやりとりしたこと、全部だ。

そして、AI が一つの会話で一度に見渡せる量には、上限がある。それをコンテキストウィンドウと呼ぶ。会話のやりとりも、AI が読んだファイルの中身も、走らせたコマンドの出力も、指示書も、全部この中に入る。昨夜の会話には、七件分の依頼と、修正の説明と、テストのログが、全部入っていた。

Claude Code の公式のドキュメントの、使い方のコツのページに、こう書いてある。

LLM performance degrades as context fills. When the context window is getting full, Claude may start “forgetting” earlier instructions or making more mistakes.

会話がいっぱいになるほど、AI の調子は落ちる。いっぱいに近づくと、前の指示を「忘れ」たり、間違いが増えたりしうる。

一晩の会話だ。さぞ長かったんだろう、と思った。長すぎたから、五件目のことを忘れた。そういうことなんだろう。

自分は、昨夜の会話の中で、キャッシュの話がどこに何回出てくるかを、上から目で追い始めた。五件目の一回目の説明に一回。二回目に一回。三回目の説明にも、外した行として一回出てくる。七件目に一回。

途中で、数え間違えている気がしてきた。眠いせいだ。手で数えるのをやめて、小さなコードを書くことにした。

// 会話の一往復。tool はコマンドの出力やテストのログ
export type Turn = { role: 'user' | 'assistant' | 'tool'; text: string };

role は、誰の発言かだ。'user' が自分、'assistant' が AI、'tool' は AI が走らせたコマンドの出力やテストのログになる。'user' | 'assistant' | 'tool' の | は、三つの文字列のどれか一つ、という TypeScript のユニオン型だ。

バッククォート（`）で囲んだ文字列の中に ${...} と書くと、そこに値が埋め込まれる。${MARK} や ${TICKET_DECISION} は、同じファイルの上のほうで決めた文字列だ。ATTEMPT_1 と ATTEMPT_2 は、一回目と二回目の AI の説明の文で、LOG_LINE は、三回目のあとのテストのログの一行だ。${MARK}, 60_000, readTickets) をつなげて読むと、cached('tickets', 60_000, readTickets) になる。MARK は cached('tickets' という文字列で、整理券の読み込みをキャッシュに通しているコードの目印だ。cached(key, ms, fn) は、うちのサーバーにある関数で、fn で取ってきた結果を ms ミリ秒のあいだ使い回す。5 * 60_000 は五分、60_000 は一分だ（数字の中の _ は、読みやすくするための区切りで、値は変わらない）。TICKET_DECISION は、票の決まりの文（運休の操作のあと、その回の整理券はすぐ使えなくする）で、IMPL_DECISION は、三回目に決めた実装の文（整理券の状態はキャッシュしない）だ。

import type { Turn } from './types.ts';

// 7件目を頼むときに AI が読む文脈。その夜の会話の全部を、順につなぐ
export function contextBefore(turns: Turn[]): string {
  return turns.map((t) => `${t.role}: ${t.text}`).join('\n\n');
}

export function parseDecisions(md: string): Decision[] {
  const decisions: Decision[] = [];
  let task = '';
  for (const line of md.split('\n')) {
    const head = line.match(/^## (\d+)\b/);
    if (head) {
      task = head[1];
      continue;
    }
    const m = line.match(/^- 決定: (.*?)(?: \/ 理由: (.*))?$/);
    if (m && task) {
      decisions.push({ task, what: m[1].trim(), why: (m[2] ?? '').trim() });
    }
  }
  return decisions;
}

一行ずつ見ていく。match は、正規表現に合った部分を取り出す。正規表現の ^ は行の頭、$ は行の終わりを表す。/^## (\d+)\b/ は、行の頭が ## で、そのあとに数字が続く行に合う。\d+ が一つ以上の数字で、\b は数字の切れ目だ。合えば、head[1] に一つ目の丸かっこ (\d+) の部分、つまり票の番号が入る。それを、いまの票の番号として覚えておく。

- 決定: で始まる行なら、決めたことの一件にする。m[1] が決めたことの文で、m[2] が理由だ。(.*?) の ? は、なるべく短く合わせる、という印で、これがあるから決めたことの文は「 / 理由: 」の手前で切れる。? がないと、理由まで決めたことの文に飲み込まれてしまう。\/ は、スラッシュそのものを表す書き方だ（正規表現の外枠にスラッシュを使っているので、中では印を付ける）。(?: \/ 理由: (.*))? は、「 / 理由: 」から後ろがあれば理由として取り出し、なければないままにする。理由がなければ m[2] は空なので、?? // 記録の不備を見つける。空なら不備なし
// ponytail: 目印だけ（``` ・行頭の ok / not ok ・却下の下の字下げ）。貼られたものを全部見分けるものではない
export function checkNotes(md: string): string[] {
  const problems = checkReasons(parseNotes(md));
  const lines = md.split('\n');
  lines.forEach((line, i) => {
    if (line.startsWith('```')) problems.push(`${i + 1}行目: コードのかたまりがある`);
    if (/^(not ok|ok) /.test(line)) problems.push(`${i + 1}行目: テストのログの行がある`);
    if (i > 0 && lines[i - 1].startsWith('- 却下:') && /^\s+\S/.test(line)) problems.push(`${i + 1}行目: 却下の続きの行がある（結論は1行に収める）`);
  });
  return problems;
}

// 引き継ぎ書を、会話ではなく記録から組み立てる。会話（Turn[]）は受け取らない
export function buildHandoff(task: Task, notes: Note[]): string {
  const problems = checkReasons(notes);
  if (problems.length > 0) throw new Error(`記録に不備がある:\n${problems.join('\n')}`);
  const line = (n: Note) => `- ${n.what}（${n.why}）`;
  return [
    `# 引き継ぎ: ${task.id} ${task.goal}`,
    '## このタスク',
    task.goal,
    '## 決めたこと（理由つき）',
    ...notes.filter((n) => n.kind === 'decision').map(line),
    '## やめたこと（もう試さない）',
    ...notes.filter((n) => n.kind === 'rejected').map(line),
    '## 範囲外',
    ...task.outOfScope.map((s) => `- ${s}`),
    '## 次の一手',
    task.next,
    '',
  ].join('\n');
}
