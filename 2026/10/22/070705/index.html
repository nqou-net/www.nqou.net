このアプリでは、データベースの形を変える手順を、マイグレーションという仕組みで管理している。マイグレーションは、表を作る・列を足す、といった変更を、番号つきのファイルに一つずつ書いておく仕組みだ。migrations/ というフォルダに、001_create_members.sql から順に、番号の付いたファイルが並んでいる。本番に出すと、まだ流していない番号のファイルだけが、番号の順に流れる。どの番号まで流したかは、データベースの中に記録が残る。

## マイグレーション

- 本番に出したマイグレーションのファイルは書き換えない。DB を変えるときは新しい番号のファイルを足す。
- migrations/ の既存のファイルは編集しないこと。変更は必ず新しい番号で。

### 絶対に守ること

hooks、という仕組みに行き当たった。

hooks は、決まった時点で必ず走るスクリプトだ。AI がツールを使う直前や直後など、あらかじめ定めた時点で、自分で書いたプログラムを走らせることができる。Claude Code の AI は、ファイルを書き換えるときも、コマンドを打つときも、道具（ツール）を呼んでそれをやる。ファイルを部分的に書き換える Edit、ファイルを丸ごと書く Write、コマンドを打つ Bash、といった具合だ。hook のプログラムは、AI がこれから何をしようとしているかを JSON で受け取って、終了コードで返事をする。終了コードは、プログラムが終わるときに返す数字だ。0 なら「通してよい」、2 なら「止める」。

export type HookInput = {

import type { HookInput } from './types.ts';

// 実測: Claude Code 2.1.300 / 2026-10-15。PreToolUse の stdin を採取した Edit / Write の入力から、
// 使うキーだけ残して作った。file_path は絶対パスで届く（session_id 等の値は省略）。
export function edit(root: string, relPath: string): HookInput & Record<string, unknown> {
  return {
    cwd: root,
    permission_mode: 'acceptEdits',
    hook_event_name: 'PreToolUse',
    tool_name: 'Edit',
    tool_input: {
      file_path: `${root}/${relPath}`,
      old_string: 'bonus_rate INTEGER',
      new_string: 'bonus_rate INTEGER, campaign_multiplier INTEGER',
      replace_all: false,

}

// 最初の案: migrations/ への書き込みは全部止める
export function buildDecide(repoRoot: string): (input: HookInput) => Decision {
  return (input) => {
    const filePath = input.tool_input.file_path;
    if (filePath === undefined) return { block: false };
    const rel = relative(repoRoot, filePath);
    if (rel.startsWith('migrations/')) return { block: true, reason: `Blocked: ${rel}` };
    return { block: false };
  };
}

relative(repoRoot, filePath) は、Node の node:path に入っている関数で、絶対パスを「リポジトリのいちばん上からの道のり」に直す。届く file_path は絶対パスなので、/work/repo/migrations/014_add_shop_bonus.sql を migrations/014_add_shop_bonus.sql にしてから、頭が migrations/ かどうかを見る。startsWith は、文字列がその文字で始まるかを調べる。buildDecide は判定そのものではなく、判定の関数を作って返す関数だ。戻り値の型 (input: HookInput) => Decision が、「HookInput を受け取って Decision を返す関数」を表している。だから使うときは、buildDecide(repoRoot)(input) と二回続けて呼ぶ。一回目で判定を作り、二回目でそれに入力を渡す。

import { relative } from 'node:path';
import type { Decision, HookInput, OnMain } from './types.ts';

export function buildDecide(repoRoot: string, isOnMain: (repoPath: string) => OnMain): (input: HookInput) => Decision {
  return (input) => {
    const filePath = input.tool_input.file_path;
    if (filePath === undefined) return { block: false };
    const rel = relative(repoRoot, filePath);
    if (rel.startsWith('..')) return { block: false };
    if (!rel.startsWith('migrations/')) return { block: false };
    if (isOnMain(rel) === 'no') return { block: false };
    return {
      block: true,
      reason: `Blocked: ${rel} は main に入っている（本番に出ている）ので、書き換えても本番には流れません。このファイルは変えず、新しい番号のファイルを足してください。`,
    };
  };
}

上から順に見ていく。file_path が無い道具なら、判定の外なので通す。道のりが .. で始まるのは、リポジトリの外のファイルなので、これも通す。migrations/ の外も通す。migrations/ の中で、main に入っていないものは通す。残った、main に入っているマイグレーションだけを止める。

道のりが .. で始まるのは、relative がリポジトリの外のファイルを ../other/x.sql のように「一つ上へ出る道のり」で返すからだ。最後の行の ? : は、条件が正しければ ? の後ろ、違えば : の後ろを選ぶ書き方だ。

import { spawnSync } from 'node:child_process';
import type { OnMain } from './types.ts';

// 利用者の git 設定（~/.gitconfig など）に答えを左右されないようにする
const env = { ...process.env, GIT_CONFIG_GLOBAL: '/dev/null', GIT_CONFIG_SYSTEM: '/dev/null' };

function git(cwd: string, args: string[]): number | null {
  return spawnSync('git', args, { cwd, env, stdio: 'ignore' }).status;
}

export function gitIsOnMain(repoRoot: string): (repoPath: string) => OnMain {
  return (repoPath) => (git(repoRoot, ['cat-file', '-e', `main:${repoPath}`]) === 0 ? 'yes' : 'no');
}

spawnSync を使うと、git のような外のコマンドを呼び出して、終わるのを待ってから先へ進める。こうして呼び出された側のプログラムを、子プロセスと呼ぶ。.status に、その終了コードが入る。stdio: 'ignore' で、git が出す文字は捨てている。見たいのは終了コードだけだからだ。env は、今の環境変数を ... で全部引き継いだうえで、git の個人設定ファイルの場所だけを中身の無い /dev/null に差し替えたものだ。個人設定によってはブランチの名前の扱いなどが変わりうるので、人によって設定が違っても、同じ答えが返るようにしてある。

// hook の本体。Claude Code が PreToolUse で起動し、標準入力に JSON を渡す
import { readFileSync } from 'node:fs';
import { spawnSync } from 'node:child_process';
import { buildDecide } from './after.ts';
import { gitIsOnMain } from './wiring.ts';
import type { HookInput } from './types.ts';

const input: HookInput = JSON.parse(readFileSync(0, 'utf8'));
const top = spawnSync('git', ['rev-parse', '--show-toplevel'], { cwd: input.cwd, encoding: 'utf8' });
const repoRoot = top.stdout.trim();
const decision = buildDecide(repoRoot, gitIsOnMain(repoRoot))(input);
if (decision.block) {
  process.stderr.write(decision.reason + '\n');
  process.exitCode = 2;
}

hook の JSON は、標準入力で届く。標準入力は、プログラムが外から文字を受け取る入口だ。readFileSync(0, 'utf8') の 0 は、標準入力の番号だ。これで、届いた文字を全部読む。JSON.parse で、それをオブジェクトに直す。git rev-parse --show-toplevel は、作業しているフォルダから、リポジトリのいちばん上の場所を教えてくれるコマンドだ。cwd があるのにわざわざ聞き直すのは、AI がサブフォルダで作業していることもあるからだ。このコマンドは答えを標準出力、つまり普通の出力の出口に書く。encoding: 'utf8' を付けると、それを文字列の stdout で受け取れる。trim() で末尾の改行を落としている。if (decision.block) の中で decision.reason が使えるのは、block が true の形にだけ reason があることを TypeScript が分かっているからだ。判定が「止める」なら、理由を標準エラーに書いて、終了コードを 2 にする。process.exitCode = 2 は、プログラムが終わるときの終了コードを 2 にしておく書き方だ。

なぜ 1 ではなく 2 なのかも、ドキュメントに書いてあった（https://code.claude.com/docs/en/hooks 、2026年10月15日参照）。

If your hook is meant to enforce a policy, use exit 2.

規則を守らせるための hook なら、2 を使え。2 だけが、止める、の意味になる。

import { relative } from 'node:path';
import type { Decision, HookInput, OnMain } from './types.ts';

export function buildDecide(repoRoot: string, isOnMain: (repoPath: string) => OnMain): (input: HookInput) => Decision {
  return (input) => {
    const filePath = input.tool_input.file_path;
    if (filePath === undefined) return { block: false };
    const rel = relative(repoRoot, filePath);
    if (rel.startsWith('..')) return { block: false };
    if (!rel.startsWith('migrations/')) return { block: false };
    const where = isOnMain(rel);
    if (where === 'no') return { block: false };
    if (where === 'yes') {
      return {
        block: true,
        reason: `Blocked: ${rel} は main に入っている（本番に出ている）ので、書き換えても本番には流れません。このファイルは変えず、新しい番号のファイルを足してください。`,
      };
    }
    return {
      block: true,
      reason: `Blocked: ${rel} が本番に出ているか確かめられませんでした（main を参照できない）。判断できないので書き込みを止めます。`,
    };
  };
}

try {

  const top = spawnSync('git', ['rev-parse', '--show-toplevel'], { cwd: input.cwd, encoding: 'utf8' });
  // リポジトリのルートが求められなければ、判断できないものとして止める

  const decision = buildDecide(repoRoot, gitIsOnMain(repoRoot))(input);
  if (decision.block) {
    process.stderr.write(decision.reason + '\n');
    process.exitCode = 2;
  }
} catch (e) {
  // Node は例外で落ちると終了コード1になり、1は「止めない」。止める側(2)に倒す

}

それから、この hook が確かめないもの。

この hook が走るのは、AI が Edit か Write を使うときだけだ。AI がコマンドを打つ Bash で、ファイルを書き換えたら、どうなるのか。迷ったけれど、試すことにした。作業用のブランチで、AI に、sed -i というコマンドで 014 の一行を書き換えてもらった。sed -i は、ファイルの中の文字を、その場で置き換えるコマンドだ。

止まらなかった。014 は書き換わった。hook は、走ってすらいなかった。matcher に書いたのは Edit と Write で、Bash ではないからだ。

コマンドを打つ道具を縛るのは、許可の設定と、サンドボックスという別の仕組みの領分らしい。今日のところは、そこまでは手を広げないことにした。この hook は、Edit と Write で、main に入ったマイグレーションを書き換える道だけを塞いでいる。ほかの道は、まだ開いている。それを、報告書にそのまま書いた。

ほかにも、書いておくことがあった。この hook は、main に入ったものが本番に出る、といううちの流れの上に立っている。流れが変われば、線の引き方も変わる。見ているのも手元の main なので、手元の main を最新にしておかないと、マージ済みのファイルを見落とす。それから、この hook が守っているのは migrations/ だけで、.claude/settings.json や hook のスクリプトそのものを AI が書き換えることは止めていない。止めたあとに AI が書く新しいファイルの中身も、この hook は見ていない。それは、これまでどおり、僕とテストが見る。

そして、テストのことだ。十本のテストが言えるのは、手で用意したサンプルの JSON を流したとき、判定と hook の本体が思ったとおりの返事をする、というところまでだ。Claude Code の側が、hook に渡す JSON の形を変えたり、設定のキーを変えたりすれば、この hook は、何も言わずに効かなくなるかもしれない。テストは緑のまま、本物の書き込みだけが素通りする。fixture の頭に、いつのどの版の Claude Code から作ったかを書き残したのは、そのためだ。設定を変えたら止まるかを確かめる、という手順も。

ついでに一つ、調べたことも書き足した。hooks と同じ考え方の、決まった時点で必ず走るスクリプトを置ける仕組みは、Codex CLI、Gemini CLI、Cursor といった、ほかのコーディングエージェントにもある（2026年10月15日に、それぞれの公式ドキュメントで確かめた範囲で）。ただ、設定を書く場所も、時点の名前も、届く JSON の形も、道具ごとに違う。うちの hook を、そのまま持っていっても動かない。

鷹宮さんは、鷹を拳に据えたまま、片手で止まり木を畳んだ。秤を小さなケースにしまう。それから、クリップボードを一枚、僕に差し出した。作業報告書だった。日付と、時間と、作業の内容が、細い字で埋まっている。

放鷹カード

  • 合図: hooks（決まった時点で必ず走るスクリプト）。規則を AI に読ませるだけにしない。書き込む直前に、こっちで確かめる。止めるときは、代わりに何をするかまで返す
  • 検め方: 書き込み先が本番に出たマイグレーション（main に入っているもの）なら、終了コード2で止める。確かめられないときも止める（onFailure は block）。設定を変えたら、わざと止まる書き込みを一度させて見る
  • 止めないもの: 新しい番号のマイグレーションを足すこと。main にまだ入っていない作りかけのマイグレーションを直すこと。マイグレーション以外のファイルを直すこと
  • 鷹のせいじゃなかった: 規則が指示書の中にしかなかった。守るかどうかを、毎回、AI が決めていた。書き込む直前に、こっちで確かめるものが何も無かった
  • 自分の言葉で: 強く書いたって、確かめるのが AI なら同じ。それと、Bash の道はまだ開いてる。明日、閉め方を調べる
