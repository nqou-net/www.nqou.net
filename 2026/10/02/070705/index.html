関数名を揃えたらモックが効かなくなった。テストは緑のまま本物が動く罠【Introduce Instance Delegator】

関数名を揃えたら、テストは緑のまま、差し替えたはずの印字処理が本物のまま動いていた。名前で縛った差し替えは名前が変わると効かなくなる。インスタンス委譲の導入（Introduce Instance Delegator）で、差し替えを渡すオブジェクトで決める形にします。

第1幕: 検分 ── 雨上がりの縁側

雨は、夜のうちに上がっていた。

樋を伝う水の音は、雨が止んでからも半日ほど残る。詰まっていれば音が濁り、通っていれば澄んで細くなる。縁側に出てその音を聞き分けるのが、雨の翌朝の、私の最初の仕事だった。今朝の音は細く澄んでいた。それでも軒先まで歩いて、樋の口に溜まった濡れ葉を手で掬い、縁側の板に落ちた滴を竹箒で寄せた。素屋根の縁からも、ときどき遅れて一粒、滴が落ちてくる。

次に、店の間へ回って印字機の出口の棚を見る。

店主は、請求書を起こす日に、その日の分を端末の中の置き場所へ置いていく。私たちはそれを待ち箱と呼んでいる。印字機は夜のうちにその箱を拾って紙にし、翌朝、出口の棚へ出す。請求書を起こすのは月末と月なかばだけで、昨日はどちらでもなかった。だから、今朝の棚は空のはずだった。

紙が三枚、載っていた。

店主の試し刷りか、書き損じだろう、と思った。角を揃えて、帳場の引き出しの端に入れた。この段取りは三十年、変わっていない。それ以上は、考えなかった。

帳場へ戻ると、クロベさんは素屋根の下での朝の見上げを終えたところだった。屋根の先の樋から軒先までを、ゆっくり目で辿るのが、クロベさんの朝の習いだ。ナギさんは文机の端末の前に座っていたが、私が上がると立ち上がった。

「印字の名前、揃えました」

背筋が伸びていた。声は抑えていたが、言い終えたあとで、ほんの少し顎が上がった。

「検めも、昨日の夕方に、全部通しています」

昨日の午後、クロベさんがナギさんに一言だけ言い付けたのを、私は聞いていた。印字の周りは、名前だけ揃えておけ。ほかの仕組みの名前は、単語を下線で繋ぐ書き方で揃っているのに、請求書を印字する関数だけは、単語の頭を大文字にして繋いだ名前だった。ナギさんは、それを一人でやり終えて、報告に来たのだった。

ナギさんは画面を私たちのほうへ向け、直した所を見せた。

package Toi::Printer;

use strict;
use warnings;

sub print_invoice {
    my ($invoice) = @_;
    open my $fh, '>', "spool/$invoice->{no}.inv" or die "待ち箱に置けません: $!";
    print {$fh} "$invoice->{customer} 御中\n";
    print {$fh} "$_->[0]\t$_->[1]\n" for @{ $invoice->{items} };
    print {$fh} "合計\t$invoice->{total}\n";
    close $fh or die "待ち箱を閉じられません: $!";
    return 1;
}

1;

package Toi::Invoice;

use strict;
use warnings;
use Toi::Printer;

sub issue {
    my (%args) = @_;
    my $total = 0;
    $total += $_->[1] for @{ $args{items} };
    my $invoice = {
        no       => $args{no},
        customer => $args{customer},
        items    => $args{items},
        total    => $total,
    };
    Toi::Printer::print_invoice($invoice);
    return $invoice;
}

1;

use strict;
use warnings;
use lib 'lib';
use Toi::Invoice;

my $invoice = Toi::Invoice::issue(
    no       => 9001,
    customer => '大和屋',
    items    => [ ['杉板', 12000], ['釘', 980] ],
);
print "合計 $invoice->{total}\n";

「本番で請求書を起こす呼び出しです。今朝までと、一字も変わっていません。printerを渡さないので、issueが自分でToi::InvoicePrinterを組み立てます。検めのほうだけが、代役を組み立てて、printer =>で渡します。代役を作って渡すのは、検めの側の書き手です」

クロベさんは、手を入れる前と後の呼び出しの道筋を、紙の上に並べて引いてみせた。

手を入れる前は、印字の関数の名前を書いている場所が、issueと検めの二か所に分かれていた。検めが指した名前は今はどこにも無く、道筋は本物のほうへしか通じていない。手を入れた後は、その名前を書いているのはToi::InvoicePrinterの一行だけになった。issueは渡された相手を呼ぶだけで、検めが代役を渡せば、道筋は代役へ折れて、本物には届かない。

「縄の手とは、どう違うんでしょう」

私が訊いた。井戸の一件のことだった。

「あのときは、同じクラスの中の呼び出しを、メソッドに切り出して、検めのときだけ子のクラスで上書きしました。今日は、関数を持っている相手の側に、薄い委譲を足して、渡すものを替えます。子のクラスは、要りません」

第4幕: 検め ── 名前を探す

同じ呼び出しを、手を入れる前のissueと、手を入れた後のissueとで、順に流して比べる。まず、それを走らせた。

比べるあいだだけ、手を入れる前の版をToi::Invoiceの名前のまま控えとして残し、手を入れた後の版をToi::InvoiceAfterという別の名前で並べて置いた。比べ終えたら、控えは下げて、新しい版がToi::Invoiceの名前を引き継ぐ。入力は、品目が一つの場合、複数の品目の場合、明細が空の場合、それから日本語の品目名を入れた場合の四つ。それぞれを、二つの版へ、同じ呼び方で流す。

普請控

  • 見立て: 請求書の印字は、Toi::Printer::PrintInvoiceという名前を呼ぶ形で組まれ、検めもその同じ名前をlocalで差し替えていた。名前を揃えた日から、差し替えの行は無い名前を指すだけになり、検めは通ったまま、本物の印字が待ち箱に三通置かれ、夜のうちに紙になって店の間の出口の棚に出ていた
  • 手を入れた所: インスタンス委譲の導入（Introduce Instance Delegator）を使った。印字の関数を呼ぶだけのToi::InvoicePrinterを作り、issueは省略できるprinterを渡してもらって、それ経由で呼ぶ。検めでは、本物の子ではない代役を渡す。前の検めのlocal三行は、代役の検めに替えた
  • 触っていない所: Toi::Printer::print_invoiceの中身（請求書の書式と待ち箱への置き方）は、一文字も変えていない。issueの呼び方、請求書の書式、店の間の印字機が夜に待ち箱を拾って紙にする仕組みも、そのまま。値札の検め（t/price_tag_seam_local.tの、Shop::Tax::rateを名前で差し替えている一行）も、今日は直していない
  • 次の工程へ送ること: 値札の検めは、名前が変われば戻り値が変わって落ちるので、急がず次に手を入れる。待ち箱の先で、印字機が紙にするところは検めていない。出口の棚に出ていた三枚の紙は、店主に見せて、処分してよいかを訊く
  • 私が引き受けたこと: 名前で差し替えている所を、自分で探して見つけられる。今日は、検めの束の中でlocal *と書かれた行を探して、四行を野帳に書き出した。探したのは、この書き方の行だけで、ほかの書き方の差し替えは、まだ見ていない。直すか、棟梁に頼むかも、まだ決めていない。見つけて、書き出すところまでは、自分でやる
