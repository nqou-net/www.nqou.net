数百行の関数の「途中だけ」をテストしたい。関数をクラスへ移して段ごとに割る【Break Out Method Object】

数百行の決算処理は途中の値がすべて関数の中に閉じていて、3段目だけを確かめられない。関数をクラスへ移し、局所変数をフィールドにする――メソッドオブジェクトの抽出（Break Out Method Object）を、呼び方も戻り値も変えずに行います。

package Daikoku::Kessan;
use strict;
use warnings;

sub settle {
    my ($sales, $rate, $day) = @_;
    my $cash    = 0;
    my $credit  = 0;
    my $gross   = 0;
    my $tax     = 0;
    my $net     = 0;
    my $rec     = 0;
    my $aged    = 0;
    my $bad     = 0;
    my $cap     = 0;
    my $reserve = 0;
    my $fee     = 0;
    my $report  = '';
    my @lines;

    # 1. 集める
    for my $s (@$sales) {
        next if $s->{void};
        if ($s->{kind} eq 'cash') {
            $cash += $s->{amt};
        } else {
            $credit += $s->{amt};
        }
        push @lines, $s->{id};
    }

    # 2. 税
    $gross = $cash + $credit;
    $tax   = int($gross * $rate);
    $net   = $gross - $tax;

    # 3. 引当
    $rec     = $credit;
    $aged    = $day > 30 ? $rec : 0;
    $bad     = int($aged * 0.10) + int(($rec - $aged) * 0.02);
    $cap     = int($gross * 0.05);
    $reserve = $bad + ($credit > $cash ? 10 : 0);
    $reserve = $cap if $reserve > $cap;
    $net    -= $reserve;

    # 4. 手数料
    $fee  = int($net * 0.01);
    $net -= $fee;

    # 5. 報告
    $report = "net=$net lines=" . scalar(@lines);

    return wantarray ? ($net, $report) : $report;
}

1;

売上の明細と税率と、決算日までの日数を受け取る。現金の売りと掛売りに分けて集め、税を引き、掛売りの回収見込みを引当として引き、手数料を引いて、最後に報告の文字列を組む。取り消された売りは、一つ目の段のnextで数えずに飛ばす。私にも、筋は追えた。

最後の行のwantarrayは、この関数を呼んだ側が結果をどう受け取ろうとしているかを、関数の中から見るための組み込みだった。呼ぶ側が並びで受け取る形（Perlでは「リスト文脈」と呼ぶ）なら純額と報告の二つを、一つの変数で受け取る形（「スカラ文脈」）なら報告だけを返す。クロベさんは、呼び出しの側の二行も見せた。

sub provision {
    my ($credit, $day, $cash, $gross, $net) = @_;
    my $rec     = $credit;
    my $aged    = $day > 30 ? $rec : 0;
    my $bad     = int($aged * 0.10) + int(($rec - $aged) * 0.02);
    my $cap     = int($gross * 0.05);
    my $reserve = $bad + ($credit > $cash ? 10 : 0);
    $reserve = $cap if $reserve > $cap;
    $net -= $reserve;
    return ($rec, $aged, $bad, $cap, $reserve, $net);
}

第3幕: 手立て ── 柱は建てたまま

クロベさんは、ここまでの三つを、順に短く言った。

「値が関数の中に閉じているから、外から見えません。切り出せば、受け渡しが増えます。入れ子にしても、古い値しか見えません。だったら、閉じている値のほうを、関数の外へ持ち出します」

それから、手立てを言った。

「長い関数を、一つのクラスに、丸ごと移します。関数の局所変数は、そのクラスのオブジェクトのフィールドにします。元の関数は、オブジェクトを一つ作ってrunを呼ぶだけの形で残します。移し終えてから、runの中身を、段ごとのメソッドに割ります」

局所変数がフィールドになれば、関数が終わったあとも、その値はオブジェクトの中に残る。外から読める。

「メソッドオブジェクトの抽出。Break Out Method Object と呼ばれる技法です」

Michael Feathers の『Working Effectively with Legacy Code』に載っている技法だと、クロベさんは言った。巨大な関数を新しいクラスへ移し、局所変数をフィールドにすると、途中の値を通して確かめられるようになる。そのかわり、割ったメソッドを単独で呼んだとき、フィールドが今何を持っているか分かりにくい、という弱点も、同じ本が認めている。私は、その二つを、野帳に分けて書いた。

「外した後に、同じ結果が出ることは、どうやって分かりますか」

私が訊いても、クロベさんは間を置かなかった。

「先に、今の戻り値を全部、書き取ります。直したあとで、同じ検めを、同じ形で通します」

並びで受け取る場合と、一つで受け取る場合の両方を、同じ入力で書き取っている。日数が三十と三十一、掛売りが現金と同じ場合と多い場合、引当が上限に当たる場合と手前の場合。三つ目の境目は、両側を取った。期待値は、正しいはずの値ではなく、今の関数が返した値の写しだ。日数の三十と三十一は$day > 30、掛売りと現金は$credit > $cash、上限は$reserve > $capという、コードの三つの条件に、それぞれ対応している。

表の十行を、並びと一つの二通りで検めて二十本。ほかに、明細を書き換えないこと、戻り値が二つだけであること、戻り値に引当の名前が出ないことを見る三本を足して、全部で二十三本になる。

package Daikoku::Kessan::Settle;
use strict;
use warnings;
use Hash::Util ();

sub new {
    my ($class, $sales, $rate, $day) = @_;
    my $self = bless {
        sales   => $sales,
        rate    => $rate,
        day     => $day,
        cash    => 0,
        credit  => 0,
        gross   => 0,
        tax     => 0,
        net     => 0,
        rec     => 0,
        aged    => 0,
        bad     => 0,
        cap     => 0,
        reserve => 0,
        fee     => 0,
        report  => '',
        lines   => [],
    }, $class;
    Hash::Util::lock_keys(%$self);
    return $self;
}

sub run {
    my ($self) = @_;
    $self->collect;
    $self->tax;
    $self->provision;
    $self->finish;
    return wantarray ? ($self->{net}, $self->{report}) : $self->{report};
}

# 1. 集める
sub collect {
    my ($self) = @_;
    for my $s (@{ $self->{sales} }) {
        next if $s->{void};
        if ($s->{kind} eq 'cash') {
            $self->{cash} += $s->{amt};
        } else {
            $self->{credit} += $s->{amt};
        }
        push @{ $self->{lines} }, $s->{id};
    }
}

# 2. 税
sub tax {
    my ($self) = @_;
    $self->{gross} = $self->{cash} + $self->{credit};
    $self->{tax}   = int($self->{gross} * $self->{rate});
    $self->{net}   = $self->{gross} - $self->{tax};
}

# 3. 引当
sub provision {
    my ($self) = @_;
    $self->{rec}     = $self->{credit};
    $self->{aged}    = $self->{day} > 30 ? $self->{rec} : 0;
    $self->{bad}     = int($self->{aged} * 0.10) + int(($self->{rec} - $self->{aged}) * 0.02);
    $self->{cap}     = int($self->{gross} * 0.05);
    $self->{reserve} = $self->{bad} + ($self->{credit} > $self->{cash} ? 10 : 0);
    $self->{reserve} = $self->{cap} if $self->{reserve} > $self->{cap};
    $self->{net}    -= $self->{reserve};
}

# 4. 手数料と 5. 報告（割らずにひとまとまり）
sub finish {
    my ($self) = @_;
    $self->{fee}  = int($self->{net} * 0.01);
    $self->{net} -= $self->{fee};
    $self->{report} = "net=$self->{net} lines=" . scalar(@{ $self->{lines} });
}

collectの中には、取り消しを飛ばすnextと、それを回すループが、そのまま入っている。ループの本体を二つのメソッドに分けなかったので、nextは、ループの中にあるままだ。式は、写したときと一字も違わない。

普請控

  • 見立て: 年に一度の決算の関数は、途中の値がすべて関数の中に閉じていて、三つ目の段（引当）だけを確かめる手立てが無かった。確かめられるのは戻り値の純額と報告だけで、引当の値は、税と手数料に挟まれて、純額の中に混ざっていた
  • 手を入れた所: メソッドオブジェクトの抽出（Break Out Method Object）を使った。決算の関数の中身をDaikoku::Kessan::Settleへ移し、局所変数をフィールドにして、集める・税・引当の三つに割った。元のsettleは、それを組んで呼ぶ一行だけを残した
  • 触っていない所: settleの名前、引数の三つ、戻り値の形（並びで受け取ったときと、一つで受け取ったときの両方）は、変えていない。呼び出し元のbin/kessan_run.plの二か所も、そのまま。各段の式の中身は、局所変数をフィールドに置き換えただけで、計算の手順は書き換えていない。手数料と報告の二段は、割らずにfinishにひとまとまりで残した
  • 次の工程へ送ること: 手数料と報告の二段を割るかどうかは、今日は決めない。割った所ごとに検めが緑なのを確かめて引き取る、という進め方を、続きでも守る。割るほど、私が読む場所が増えるので、確かめられる量に収めるため
  • 私が引き受けたこと: 大物の直しを、割る所と割らない所に分けて、私から頼める。今日は、集める・税・引当の三つまでを割り、手数料と報告は割らないと決めて、その理由（私が説明できるのは三つ目まで。割った数だけ、私が読む場所が増える）を添えて、クロベさんに頼んだ。頼んだ範囲を引き取れるかどうかは、割った所ごとに、挙動が移す前と同じかどうかを、検めの緑で私が確かめる
