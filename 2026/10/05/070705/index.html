単体テストは全部緑なのに締め処理が壊れる。1か所のテストで全体を守る【Pinch Point】

部品ごとの単体テストは全部緑なのに、月末の締め処理を通すテストは1本も無い。影響が集まる1か所にテストを1本だけ置く締め所（Pinch Point）を、部品を1つずつわざと壊して確かめながら Perl で書きます。

第1幕: 検分 ── 夜明け前の帳場

今朝は、私のほうが先に帳場にいた。

素屋根の隙間は、まだ灰色だった。畳に、光の筋は落ちていない。柱の影と、柱と柱のあいだの暗さの区別が、つかないほどだ。夜のうちに冷えた畳の匂いが、足元から上がってくる。文机の上の灯りだけをつけて、私は野帳を開いた。クロベさんもナギさんも、来ていなかった。素屋根の下に、人の気配が無い時間は、一日のうちで、この朝の一時間ほどしかない。

この野帳は、工事が始まった日から付けてきた控えだ。工程ごとに節が分かれていて、一つの節の終わりには、その日の普請控を写してある。節の縁を、一つずつ折ってあった。頁を繰りながら、折った縁を数えた。十一あった。

昨日の夕方、店主さんに訊かれた。素屋根が外れたあと、勘定のことは、あなたに訊けばいいのですね、と。私は、はい、と答えた。答えてから、何を見て大丈夫だと言うのか、自分が言えないことに気づいた。

野帳の節ごとに、検めの置き場が一つずつある。端末の中で、工程の名前の付いた別々の置き場に分かれていて、走らせ方も、野帳の節の端に控えてあった。

音の止んだ帳場で、ナギさんの紙を、野帳の一頁に写した。左の端に、十の頼みを並べた。矢印の出た七つは、細い墨の線で泡へ引いた。矢印にならなかった三つは、線を引かず、頁の余白に書き留めた。泡は実線にして、この図で線の寄らない値札と印字機だけを、薄い墨の破線にした。運賃と決算と大福帳と知らせから右へ引いた線は、太くした。税率の関数から出る線だけは、細く下の隅へ向けた。太い線が寄る先には、点線で輪郭だけを写した。

第3幕: 手立て ── 一か所に置く

クロベさんが、砥石を置いて、卓のほうへ向き直った。

「工事が終わったあとに来る頼みの届く先が、細く集まっている所があります。そこに検めを一つ置けば、集まる分については、少ない検めで、広い範囲の変化に気づけます。本では、Pinch Pointと呼ばれています。日本語の本では、絞り込み点と訳されています」

本が言っているのは、三つだと、クロベさんは続けた。集まる所は、頼みの組で決まる。組が変われば、その一か所も変わる。広く集めすぎると、行き詰まる。もう一つ、そこに置いた検めは、あとで部品ごとの検めが揃えば、消えてよい足場だということ。

「変更の近くに置く検めは、原因に近い。集まる所に置く検めは、少なくて済みますが、原因からは遠いです」

「その一か所は、どうやって決めるんですか」

私が訊ねると、クロベさんの視線が、野帳に落ちた。

「あなたの野帳の十行です。工事が終わったあとに来る頼みの組で決まります」

十行は、私が自分の手で書いてきた欄の写しだった。

package Choba::Shime;
use strict;
use warnings;
use Shop::Tax;
use Delivery;
use Daikoku::Kessan;
use Nikai::Daifuku;
use Omote::Shirase;

# 月末の締めの入口。新しい計算は持たない。店主の手順（部品を呼ぶ順番）を書き写しただけ。
# 書き写しでなく決めたことは一つだけ: 税率は kessan_run.pl のように 0.1 と手で書かず、税率の関数（Shop::Tax の rate）から取る。
sub run {
    my (%arg) = @_;
    my $rate = Shop::Tax::rate();
    my $fee  = Delivery::calc_fee(@{ $arg{parcel} });
    # settle は list 文脈で受ける（scalar だと report だけが返る）
    my ($net, $report) = Daikoku::Kessan::settle($arg{sales}, $rate, $arg{day});
    my $daifuku = Nikai::Daifuku->new(path => $arg{path}, ledger => $arg{ledger});
    $daifuku->post($arg{date}, '日計', $net);
    $daifuku->post($arg{date}, '配達', $fee);
    my $shirase = Omote::Shirase->new(line => $arg{line});
    $shirase->close_month($report);
    return { net => $net, report => $report, fee => $fee };
}

1;

第4幕: 検め ── 壊して、赤になるかを見る

壊して確かめる、とは、部品を一か所だけわざと壊して、検めがそれに気づくかを見ることだ。壊した版は、コピーしたツリーの中で作る。本物のlibには、触れない。同じ壊し方を、その部品の元の置き場の検めにも当てて、結果を並べる。

ナギさんが、四十七の壊し方を、一つずつ入れて走らせた。同じ結果になるはずの書き換え（//を||に替えるなど）が三つ混ざっている。残る四十四が、本当の壊しだ。そのうち八つを、表にした。壊して確かめるのは、検めが本当に何かを守っているかを、検める側から確かめるためだ。

壊し方入口の検めその部品の元の検め読み方
税率の関数を八分に書き換える赤赤（値札の置き場だけ）税率の書き換えを、入口の検めが見張っている
30日超の境目の>を>=に九件なら赤、先頭の一件だけなら緑赤境目を踏む入力が要る
手数料と報告の順を、誤って割る赤赤割る作業の見張りになる
入口が知らせを、帳面より先に出す赤（帳面が開けないときの検めで）部品側に検めが無い入口の配線は、入口の検めだけが見張る
重さの境目の> 5を>= 5に赤緑部品の検めが足りない
負の金額の△を-に緑赤入口が入れない値
close_dayの知らせを消す緑赤入口が呼ばない関数
値札が税を足さない緑赤入口を通らない部品

四十四のうち、入口の検めが赤にしたのは三十四。赤にしなかったのは十だった。

入口は、部品を呼ぶ順を書き写しただけだ。だから、部品を壊せば赤になるのは、当たり前に見える。当たり前でないのは、二つある。部品の検めが緑のままなのに、入口の検めだけが赤になる壊し方。それから、入口の配線そのものを壊したとき、元の置き場の検めには、見張る相手がいない。表の四行目と五行目が、それだ。

二行目は、件数の実演だ。検めを日数45の一件だけにすると、30日超の境目は、踏まれないので緑のままだ。九件に戻すと赤になる。こういう壊し方は、全部で九つあった。30日超の境目、重さの境目、距離の境目、遠方の境目、税の端数、期日の二つの率、上乗せの条件と額。件数ではなく、境目を踏む入力が効く。

六行目から八行目が、赤にならなかった所だ。理由は三つに分かれた。入口が入れない値域（負の金額は、入口から一度も入ってこない）。入口が捨てる値（大福帳のpostの戻り値、知らせの控え）。入口が呼ばない関数と、入口を通らない部品（close_day、値札）。つまり、赤にならなかった十は、入口の検めの穴ではなく、入口の検めの範囲の外だ。

私が言うと、クロベさんは、一度だけ頷いた。

「あります。それを先に言うのが、締め所の仕事の半分です」

五行目は、別の話だった。入口の検めは赤なのに、その部品の元の検めは、緑のままだった。ナギさんが、運賃の置き場の検めを開いた。境目を踏む入力が、そこには無かった。重さの境目のほか、距離の境目、知らせの文面、帳面が開けないときの言葉の三つが、同じように、元の検めには引っかからなかった。

入口の検めが赤になって、部品の検めへ降りても、緑のまま、原因が見つからない。そういうことが、この四つで起きた。入口の赤は、部品の検めが足りない、という知らせにもなる。

だから、検めは二段になる。一段目は、入口の検めで、全体に届いたかを見る。赤なら、二段目の部品の検めへ降りて、どの部品かを探す。二段目が、緑のまま空振りするときは、その部品の検めが足りない。表の五行目が、それだ。

次に、この検めが言えることと、言えないことを、野帳の十行に当てた。

入口を通って、出力に載り、固定入力が踏む変化には、気づける。それが、入口の検めが言えることだ。

持ち越し入口の検めは根拠
一月ぶんだけの検め肩代わりしない（野帳へ送る）九件の入力しか見ない。足した分だけ広がる
ずれが間違いか決まりかの判断野帳へ送る赤は、変わった、としか言えない。判断は人
税率の書き換え肩代わりする入口が税率の関数から取るので、八分で赤になる
値札の検め野帳へ送る値札は入口に載らない
本物のファイルに触れるか肩代わりする帳面を見る検めで、触れる壊し方が赤になる
取り込む箇所が増えたとき野帳へ送る入口は取り込みの箇所を数えない
先月の三角の書き方野帳へ送る入口は正の金額しか積まない
大福帳が開けないとき肩代わりする（止まり方と順序）何と言って止まるべきかは野帳
待ち箱の先の印字機野帳へ送る入口が読み込まない
手数料と報告の二段割る作業の見張りは肩代わり、割るか否かは野帳へ誤った割り方は赤になる

範囲の外も、先に言っておかなければならない。日の締めは、入口が写していない。九件以外の入力は、見ていない。入口を通らない部品と、入口が捨てる値は、見えない。本物の大福帳、書状が店主に実際に届くかも、見ていない。これは、九件を一度動かした話だ。毎日使い続けている店の中で何が起きるかは、この九件からは分からない。

私は、野帳の六つ目の節を開いた。前に私が書き残した宿題が、そこにある。通る場所が本当に一つと言えるのはどんなときか、というものだ。ここでは、部品を呼ぶ所が、入口だけと言えるのか、という問いに引き直せる。

「呼ぶ所は、一つ、と言ってよいんですか」

ナギさんが、素の名前で、探した。

検めの側を除けば、どちらも呼ぶ所は二つだった。税率の関数は、入口と値札から。大福帳は、入口と、帳面だけを書くbinの一本から。

クロベさんが答えた。

「言えません。言えるのは、木の中の全部を素の名前で探して、呼ぶ所が入口だけだったときです。それでも、名前を組み立てて呼ぶ所は、探しても出てきません。木の外のものは、数えられません」

私は、野帳に、二行足した。入口のほかに、呼ぶ所が二つあること。木の外は、外に聞くしかないこと。

最後に、消し方の話があった。

「この検めは、重さと距離の境目、知らせの文面、帳面が開けないときの言葉、この四つの部品の検めが揃うまで、消さないでください。元の検めに引っかからなかった四つです。それが揃えば、入口の検めの重なる分は、消せます。入口の配線の検めは、入口がある限り残します。入口が部品を正しく呼んでいるかは、部品の検めには見えないからです」

そのあと、クロベさんは、何も言わなかった。ナギさんが、端末の席から立った。空いた席に、私が座った。

私は、税率の関数を、八分に書き換えた。入口の検めを走らせる。赤だった。帳面の行と、戻り値の数が、期待と違う。値札の検めも、赤。決算の置き場は、緑のままだ。関数を元に戻して、走らせ直した。緑だった。

野帳に、赤になったときの順を、書いた。

クロベさんが、一度だけ訊いた。

「赤になったら、どうしますか」

私は、野帳の行を見ながら、答えた。

「入口の検めが赤になったら、何が変わったかを読みます。戻り値か、帳面か、知らせか。次に、部品の検めを順に走らせて、赤の部品を探します。部品が全部緑なのに、入口だけが赤なら、入口の配線か、部品の検めが足りません。意図した変更なら、期待値を書き換える前に、店主さんに確かめます」

「それでも、どの部品か特定できなかったら」

「外へ頼みます。野帳と控えを添えて。野帳を見せれば、別の大工さんにも、今日までのことが伝わります」

クロベさんは、答えなかった。砥石を持った手を、膝の上に置いた。ナギさんは、立ったまま、道具箱の蓋の留め金に指をかけて、動かなかった。

翌朝は、昨日より早く起きた。

素屋根の隙間は、まだ灰色だった。梁の下に、クロベさんが立っていた。私は、梁の下の、クロベさんの隣に立った。これまで、見上げる背中を、後ろから見ていた。同じ高さから見上げるのは、初めてだった。

隙間の筋が、畳の上を、ゆっくり渡っていく。梁の継手に、細い光が斜めに当たる。鉋屑が、その中を降りてくる。

「今日の形は、このまま残しておいてください。直す前の形を残しておかんと、直ったかどうかが言えません」

クロベさんが、見上げたまま言った。

最初の日に、この帳場で聞いたのと、同じ言葉だった。

二人は、道具箱を土間へ運び出した。鉋と鑿と墨壺が、箱に収まっていく。蓋を閉じるたびに、留め金が、短く鳴った。ナギさんは、運び出す前に、端末の脇へ、紙を一枚貼っていった。土間の石を、箱を提げた足音が、遠ざかっていく。二人の口から、言葉は出なかった。

足音が聞こえなくなってから、私は端末の脇の紙を見た。一行だけ、書いてある。

普請控

  • 見立て: 十一の置き場の検めは、部品ごとには緑でも、月末の締めを通した全体を一度に確かめる手立てが無かった。税率の関数を書き換えても、決算の検めは赤にならなかった。
  • 手を入れた所: 締め所（Pinch Point。邦訳では絞り込み点）に検めを一つ置いた。月末の締めの手順を一本の入口Choba::Shime::runに書き写し、九件の入力で、戻り値と大福帳の行と知らせを書き取った。部品を四十四通りに壊して、その検めが気づくかを確かめた。
  • 触っていない所: Shop::Tax・Delivery・Daikoku::Kessan・Nikai::Daifuku・Omote::Shiraseの五つの部品は、元の置き場から写しただけで、一字も変えていない（大福帳だけ、手を入れた後の形を本体の名前に戻したpackageの一行のみ）。binの三本、値札PriceTag、日の締めのclose_day、待ち箱の先の印字機、先月までの帳面の中身、書状が店主に実際に届くか、十一の置き場の検めそのもの。
  • 次の工程へ送ること: 野帳へ送った七つ（一月ぶんだけの検め、ずれの判断、値札、取り込む箇所、先月の三角、印字機、二段を割るか）。重さと距離の境目、知らせの文面、帳面が開けないときの言葉の部品の検めを足すまで、入口の検めは消さない。税率が変わるとき、値札と月末の締めを一緒に動かしてよいかは、店主さんと決める。
  • 私が引き受けたこと: 入口の検め一本を自分で走らせ、赤なら部品の検めへ降りて原因を探し、特定できないときだけ、野帳と控えを添えて外へ頼む。棟梁を呼ばなくてよい。自分の手で税率の関数を書き換えて赤を出し、赤を読んで順を書き、訊かれて答えた。
