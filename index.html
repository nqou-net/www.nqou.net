数百行の関数の「途中だけ」をテストしたい。関数をクラスへ移して段ごとに割る【Break Out Method Object】

数百行の決算処理は途中の値がすべて関数の中に閉じていて、3段目だけを確かめられない。関数をクラスへ移し、局所変数をフィールドにする――メソッドオブジェクトの抽出（Break Out Method Object）を、呼び方も戻り値も変えずに行います。

Tech

関数名を揃えたらモックが効かなくなった。テストは緑のまま本物が動く罠【Introduce Instance Delegator】

関数名を揃えたら、テストは緑のまま、差し替えたはずの印字処理が本物のまま動いていた。名前で縛った差し替えは名前が変わると効かなくなる。インスタンス委譲の導入（Introduce Instance Delegator）で、差し替えを渡すオブジェクトで決める形にします。

Tech

コンストラクタが本番の帳簿ファイルを開いてしまうクラスを、テストできる形にする【Parameterize Constructor】

組み立てた途端に本番の帳簿ファイルを開いてしまうクラスは、そのままではテストできない。コンストラクタのパラメータ化（Parameterize Constructor）で、依存を外から渡しても渡さなくても動く形にします。

テストのたびに外部 API を叩いてしまうコードを、サブクラスで差し替える【Extract and Override Call】

郵便番号の引き当てがテストのたびに外部へ問い合わせてしまう。取り込んだ関数には local が届かない――呼び出しの抽出とオーバーライド（Extract and Override Call）でテスト用のサブクラスに差し替えます。

呼び出し元を1行も変えずに、全箇所へログを仕込む【Wrap Method】

呼ばれている箇所が数えきれない処理に、出入りをすべて記録する決まりができた。包みメソッド（Wrap Method）で呼ばれる側だけを変え、呼び出し元は1行も変えずにログを効かせます。

テストで組み立てられないクラスへの機能追加は、新しいクラスを別に起こす【Sprout Class】

既存の在庫クラスはコンストラクタで帳簿ファイルを開くため、テストの中で組み立てられない。判定ロジックを芽生やしクラス（Sprout Class）として別に起こし、既存クラスからは委譲するだけにします。

既存の配達料計算に遠方割増を足したい。既存関数に直接書き足さず、新しい処理を芽生やしメソッド（Sprout Method）として別に作り、既存には呼び出し1行だけを足します。

差し替える場所が無いように見える Perl コードでも、パッケージ境界そのものが継ぎ目（Seam）になる。シンボルテーブルを local でテストの間だけ差し替え、本体を書き換えずに税率計算を確かめます。
